## Pass A: application threat/data-flow model

Actors: local user, FusionCanvas desktop process, Printify API, Printify image hosts. Assets: Printify bearer key; shop listing metadata and identifiers; original artwork bytes; local workspace item, mapping, and managed asset records. Boundaries: local credential store to API request; API response to parser; API-supplied image URL to bounded download; downloaded bytes to managed workspace files and item links. Proposed shop behavior is read-only; the HTTP client uses GET, fixed API base, and the artwork client uses an allowlist and no auto-redirect. Threats considered include malicious/malformed remote payloads, oversized responses, unsafe URLs, wrong image types, credential leakage, duplicate mapping, and local file path traversal.

## Pass B: surface/privacy flows

- Listing import surface: Store-scoped credential and shop selection; GET-only shop/product requests; product identity validation; one-to-one mapping guard; local persistence. Source: Application service and Integration client.
- Artwork acquisition surface: HTTPS allowlist for two hosts, auto-redirect disabled, 30-second timeout, 20 MiB limit, content-type and signature validation; path uses the managed file store; provenance query/fragment stripped before persistence.
- Privacy flow: Printify listing metadata (title, description, visibility, variants, print areas, IDs) moves from Printify API into local Item-linked snapshot/mapping. Purpose: user-requested listing bootstrap. Retention follows Item/workspace lifecycle; exact deletion lifecycle not traced in this bounded run (`UNKNOWN`).
- Privacy flow: original artwork moves from Printify image hosts into managed local assets linked to an Item for offline reuse. User explicitly confirms import. Workspace deletion/backup/export behavior follows shared asset/workspace controls; end-to-end deletion/recovery paths not fully inspected (`UNKNOWN`).
- Privacy flow: Store credential is read from existing credential store and sent as bearer auth to Printify API. Credential storage/removal is pre-existing and outside the changed code; not audited end to end here (`PARTIAL`).

No confirmed feature-specific vulnerability was found in the reviewed boundary code. This is not a certification of the full credential lifecycle, local workspace protection, or every provider response path.
