## ADDED Requirements

### Requirement: Niche population is available only for eligible drafts
FusionCanvas SHALL provide a `Populate` action in the focused Store Management → Niches editor for a new niche draft or selected non-archived niche whose current niche name contains non-whitespace text. The action SHALL be unavailable while the General AI configuration is not ready, and the UI SHALL explain that AI settings must be configured before population can start.

#### Scenario: Eligible new niche has a configured General model
- **WHEN** the user is editing a new non-archived niche draft, the niche name is non-blank, and the General AI configuration is ready
- **THEN** the `Populate` action is enabled

#### Scenario: Eligible existing niche has a configured General model
- **WHEN** the user is editing a selected non-archived niche, the niche name is non-blank, and the General AI configuration is ready
- **THEN** the `Populate` action is enabled

#### Scenario: Name is blank
- **WHEN** the current niche name is empty or whitespace-only
- **THEN** the `Populate` action is disabled
- **AND** no AI request is started

#### Scenario: General AI is unavailable
- **WHEN** the current niche name is non-blank but the General AI configuration is missing a model, credential, or valid configuration
- **THEN** the `Populate` action is disabled
- **AND** the UI identifies the missing prerequisite and directs the user to AI settings

#### Scenario: Archived niche is selected
- **WHEN** the selected niche is archived
- **THEN** the `Populate` action is disabled
- **AND** no AI request is started

### Requirement: Population requests independent suggestions for selected blank fields
FusionCanvas SHALL ask the General AI model for independent suggestions based on the current niche name and SHALL request suggestions only for blank eligible fields: Description, Audience, Humor style, Visual style guidance, Constraints, and Notes. Risks and Research notes SHALL NOT be generated by this action. The request SHALL treat the niche name as untrusted creative data and SHALL instruct the model that visual-style guidance must target typical print-on-demand t-shirt graphics that are wearable, legible, scalable, and suitable for common DTG or screen-print workflows.

#### Scenario: Request contains only blank eligible fields
- **WHEN** the user activates `Populate` with a non-blank niche name
- **THEN** the AI request contains the current niche name and the names of the currently blank eligible fields
- **AND** non-blank eligible fields are excluded from replacement input
- **AND** Risks and Research notes are excluded from the requested output

#### Scenario: Request uses the General AI purpose
- **WHEN** a population request is assembled
- **THEN** it uses the General AI configuration and provider path
- **AND** it does not require a niche-specific AI settings profile

#### Scenario: Visual style guidance is print-on-demand oriented
- **WHEN** Visual style guidance is one of the blank requested fields
- **THEN** the request asks for guidance relevant to typical print-on-demand t-shirt graphics
- **AND** the request excludes mockup photography, garment presentation, and product-styling direction from that field

#### Scenario: AI returns structured independent values
- **WHEN** the provider returns a valid structured response
- **THEN** each returned eligible field is interpreted independently
- **AND** unknown fields, Risks, and Research notes are ignored

### Requirement: Population applies only editable drafts and never saves automatically
FusionCanvas SHALL apply successful population results only to the in-memory niche editor draft. The existing niche name SHALL remain unchanged, generated values SHALL remain user-editable, and the user SHALL explicitly activate the existing Save action to persist them.

#### Scenario: Blank fields receive suggestions
- **WHEN** a successful response contains non-whitespace values for requested blank eligible fields
- **THEN** those values appear in their corresponding editor fields
- **AND** the niche name remains unchanged
- **AND** Risks and Research notes remain unchanged

#### Scenario: Existing values are preserved
- **WHEN** a successful response is applied while one or more eligible fields already contain non-whitespace text
- **THEN** those existing values remain unchanged
- **AND** only fields that were blank when the request began may be filled

#### Scenario: Suggestions are not persisted automatically
- **WHEN** population applies one or more suggestions
- **THEN** the editor reports unsaved niche changes
- **AND** the workspace repository is not updated until the user activates Save

#### Scenario: User edits a suggestion before saving
- **WHEN** the user changes a populated field and activates Save
- **THEN** the edited value, rather than the original suggestion, is persisted through the existing niche-management save path

### Requirement: Population handles busy, failure, and incomplete responses safely
FusionCanvas SHALL expose a busy state while population is in progress, prevent overlapping population requests, and return to a stable editable state after success, failure, cancellation, or an incomplete response. Failed or unusable responses SHALL preserve all existing editor values and SHALL expose recoverable user-safe guidance without displaying credentials or raw provider payloads.

#### Scenario: Population is in progress
- **WHEN** a population request is running
- **THEN** the `Populate` action is disabled
- **AND** the editor shows a distinguishable in-progress state
- **AND** a second population request cannot start

#### Scenario: Provider request fails
- **WHEN** the AI provider reports a failure
- **THEN** the editor returns to a non-busy state
- **AND** existing field values remain unchanged
- **AND** the UI reports a recoverable error

#### Scenario: Provider returns no usable values
- **WHEN** the provider response is malformed, empty, or contains no usable eligible field values
- **THEN** the editor returns to a non-busy state
- **AND** existing field values remain unchanged
- **AND** the UI reports that no usable suggestions were returned

#### Scenario: Settings change while the editor is open
- **WHEN** the user changes General AI settings while the niche editor is open
- **THEN** population availability is re-evaluated without reopening the editor

### Requirement: Population respects the focused editor interaction model
FusionCanvas SHALL place `Populate` beside the niche name input in the focused Niches editor, keep it in predictable keyboard order, provide a meaningful accessible name, and preserve the existing discard-confirmation behavior for generated unsaved values.

#### Scenario: User reaches Populate by keyboard
- **WHEN** keyboard focus traverses the niche editor from the niche name field
- **THEN** the `Populate` action is reachable before the following niche context fields
- **AND** its accessible name identifies the population action

#### Scenario: User closes after population without saving
- **WHEN** population has changed one or more draft fields and the user attempts to switch niche, close the editor, or start another niche draft
- **THEN** the existing discard-changes confirmation is shown
- **AND** declining discard keeps the generated values in the current editor

#### Scenario: User saves after population
- **WHEN** the user explicitly saves after reviewing or editing generated values
- **THEN** the normal niche save flow remains the sole persistence path
