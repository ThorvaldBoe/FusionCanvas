## Context

The Design stage has a deterministic default prompt, an Item-specific prompt override and contrast choice, image generation, and endpoint capability data that includes maximum input-reference counts. `AiImageGenerationRequest` and the OpenRouter adapter already serialize multiple image references. The current generation path sends no references and the prompt compiler includes Niche visual-style guidance.

Workspaces are first-class records in the shared SQLite snapshot. Large files use a workspace-relative managed-file store. Workspace packages serialize a filtered snapshot and include files referenced by assets. There is not yet a workspace-scoped reusable artwork-style entity or a package relationship for its reference images.

The existing prompt behavior is recorded in the completed `editable-artwork-prompt-and-image-edits` change, but its prompting capability is not present under `openspec/specs/`. This change defines the style-selection capability independently and does not depend on syncing that historical spec.

## Goals / Non-Goals

**Goals:**
- Manage reusable artwork styles in one workspace, each with a title, description, and ordered managed image references.
- Make General the immutable built-in default for Items without a valid custom-style selection.
- Select a style in Design, compile its description into the default prompt, and send its complete references with generation when the endpoint supports them.
- Replace Niche visual-style guidance with the selected style, while retaining other applicable Niche context.
- Include style records, Item selections, and referenced files in workspace persistence and transfer.
- Keep frequent style selection in Design and occasional creation/edit/delete in a focused management surface.

**Non-Goals:**
- Cloud sharing, cross-workspace styles, style tagging/search, style previews generated by AI, or style inheritance.
- Automatic selection of a subset when a style has more references than the image endpoint can accept.
- Changing explicit prompt-override semantics, image editing's one-current-artwork input, or image-provider contracts that already support multiple references.
- Making General editable or deletable.
- Real-desktop Appium coverage; the accepted flows are representable with deterministic repository/file-picker collaborators and Avalonia headless views.

## Decisions

### Workspace-scoped persisted styles

Add a Domain style record owned by Workspace and an ordered reference record that points to a managed workspace-relative file. Keep title and description as structured fields. Include style records in `WorkspaceSnapshot`, repository load/save, snapshot filters, and transfer serialization. Use Item metadata for the selected style ID to match current per-Item prompt and contrast preferences; a missing or invalid ID resolves to General. General is a stable built-in option and is not persisted as a style row.

Custom style title and description are required. Titles are unique within a workspace after trimming and case-insensitive normalization. Each style must retain at least one valid image reference. Reference order is durable and all references are used together.

### Atomic style lifecycle and Item fallback

Create/update operations stage new managed files before saving structured state, then clean staged files on failure. Removed files are deleted only after the saved relationships no longer reference them and a repository-wide workspace reference check confirms they are unused. Deleting a custom style requires confirmation; in the same repository transaction it replaces matching Item style IDs with the General/default representation while preserving all unrelated Item metadata. General cannot be changed or deleted.

Style edits use an explicit Save action. Switching records or closing the focused management window with a meaningful draft asks to discard or keep editing. When an Add new flow returns to Design, the just-created style becomes available and selected for the originating Item.

### Focused management surface and compact Design selection

Workspace settings expose a Manage artwork styles entry. Design presents a compact style selector next to artwork prompt/generation controls and an Add new shortcut. Add new opens the same active-workspace management surface while retaining the Item context; successful creation selects the new style on return. The management surface uses a scannable style list and one focused selected-or-new editor, with an image collection showing order, availability, add/remove, and preview. Empty, loading, validation, save-failure, missing-file, busy, and read-only states are explicit. Selection changes in Design save with the Item using the existing preference persistence path.

### Style replacement in prompt compilation

When General is active, omit both custom style text and the Niche `visualStyleGuidance` field. When a custom style is active, include its title and description as delimited untrusted creative data and omit only Niche visual-style guidance; audience, humor style, and constraints remain eligible. The explicit custom style is therefore the sole source of visual-style direction in the compiled default. Other prompt safety, phrase, composition, and print constraints remain unchanged.

If the compiled default is active, selecting another style recompiles it immediately. A saved explicit prompt override remains byte-for-byte the active prompt under the existing prompt-editor contract; the selected style's reference images still accompany generation, and Reset to default compiles the currently selected style description. This preserves creator control without silently rewriting an override.

### Complete reference set or no request

The generation service resolves all selected style references through the managed file store, validates and encodes each supported image, and passes them in saved order through the existing `AiImageGenerationRequest.InputReferences` contract. Generation is available only if every style reference can be prepared and endpoint `MaxInputReferences` is at least the style reference count. If not, show actionable guidance and submit no partial request. General sends no references and does not require endpoint reference support. Missing files and provider/persistence failures leave Item/style state unchanged. Recheck Item and selected style identity after provider completion before persisting output, following current stale-context protections.

### Portable workspace migration

Add the style and style-reference tables through the ordered SQLite migration chain with workspace ownership and restrictive relationship constraints. Existing databases migrate additively: no styles means General is effective, so no row backfill or Item rewrite is needed. Workspace import/export includes style records, ordered references, and every available referenced file, and reports missing files using existing transfer behavior. Import validates ownership, uniqueness, image references, and paths before applying changes, preserving the package's atomic import semantics.

## Risks / Trade-offs

- **[Risk]** Styles may exceed an endpoint's reference capacity. → Disable generation for that selection/model and explain how to proceed; never silently drop references.
- **[Risk]** Deleting a style affects multiple Items. → Show the number of affected Items in confirmation and atomically return them to General.
- **[Risk]** Managed images may be shared or missing. → Delete files only after a reference check; report missing references and block generation until repaired or removed.
- **[Risk]** A custom prompt override can omit the selected style description. → Preserve exact override behavior, always send the selected style's image references, and make Reset to default the explicit way to recompile text guidance.
- **[Risk]** Workspace package compatibility is affected by new structured records and files. → Increment the SQLite schema additively, retain ordered migrations, and cover old-schema migration plus package round trips.
- **[Risk]** Style description and images may contain prompt-injection-like content. → Keep the existing untrusted-workspace-content prompt boundary for style text and exclude operational metadata, paths, and credentials from prompts.

## Migration Plan

1. Add an additive workspace database migration for style records and ordered managed reference associations; retain compatibility with existing schema versions.
2. Add snapshot/repository/filter support and extend package writers/readers and manifest entity counts/file enumeration.
3. Migrate existing Items implicitly through the General fallback; do not rewrite their metadata.
4. Ship the focused management surface and Design selector together with generation support so no saved custom style is unusable.
5. On rollback, the prior build can ignore newer package versions as it does today; its existing local database behavior for unknown additive tables must be verified before implementation. Do not drop style tables or files as part of rollback.

## Open Questions

None. The endpoint capacity behavior, deletion fallback, built-in General behavior, and prompt precedence are explicit above.

## Implementation Plan

1. **Domain and workspace snapshot**
   - Add `ArtworkStyle` and `ArtworkStyleReference` Domain records with stable IDs, owning `WorkspaceId`, title/description, ordered managed-file reference, media type, and timestamps.
   - Extend `WorkspaceSnapshot` with styles/references and update snapshot filtering/validation in `Domain/Workspace` and transfer filters. Enforce ownership and ordered-reference invariants in Application use cases; General remains a built-in selector option, not a row.

2. **SQLite and managed files**
   - Add schema version 24 migration in `Integration/Persistence/SqliteWorkspaceRepository.cs` and `SqliteDatabaseSchema.cs` for style and reference tables, normalized unique title constraint per workspace, cascading style-reference ownership, and indexed workspace lookup.
   - Extend repository load/save/replace, mapping, transaction validation, and schema round-trip tests. Keep Item selected style ID in existing metadata JSON.
   - Add managed reference import/read/preview/removal orchestration using current `IWorkspaceFileStore`/output-store boundaries. Validate path containment; stage writes and clean them after failed structured saves; remove old files only after confirming no remaining links.

3. **Style management use case**
   - Add workspace-scoped list/create/update/delete requests and results plus an Application management service/contract under `Application/ArtworkStyles` (or existing workspace capability folder where conventions require).
   - Normalize/validate titles and required fields; preserve stable IDs/order; return affected Item count; transactionally set matching Item style metadata to General representation on delete.
   - Add deterministic Application tests for scope isolation, duplicate/blank validation, atomic create/update/delete, fallback preservation of unrelated metadata, shared references, missing files, and cleanup on failure.

4. **Workspace transfer**
   - Extend snapshot package serialization/deserialization, export file enumeration, counts, missing-file manifest entries, import preflight/ownership validation, and atomic insert/rollback in `Integration/Workspaces/Transfer` and `Application/Workspaces/Transfer`.
   - Add tests for new-schema round trips, older schema migration, ordered reference preservation, missing files, duplicate IDs/ownership rejection, and selected Item rehydration.

5. **Prompt and image generation**
   - Extend `ArtworkPromptCompiler`/prompt context to read the Item's style ID, compile custom title/description, omit Niche visual guidance, and retain other Niche fields; General omits style and Niche visual guidance.
   - Extend `DesignStageState`, `IDesignStageService`, and `DesignStageService` with available styles, selected style identity, and preference persistence. Recompile only while the generated default is active; preserve explicit overrides.
   - Extend `ArtworkGenerationService` to resolve the full ordered reference set, validate endpoint capacity and supported media, send bytes using the existing multiple-reference contract, and recheck context before save. General sends no references. Add Application tests for request order/content, capacity mismatch, missing/invalid reference, explicit overrides, General, cancellation, and stale context.

6. **Avalonia user flows**
   - Add the style selector and Add new action to `StageTools/DesignStageToolViewModel` and the artwork section in `Views/MainWindow.axaml`; bind capability explanations and preserve Item/editor focus during the management round trip.
   - Add a focused style-management view/view model and launcher from `Settings`/`Workspace` management. Follow master-detail, workspace inset, compact command, save/discard, and destructive confirmation guidance. Use injected file-picker and image-preview boundaries.
   - Add framework-free view-model tests and Avalonia headless tests for selection, Add new return-and-select, saved re-entry, General/custom prompt transitions, disabled capacity/missing-file states, validation, draft discard, deletion impact confirmation, and focus/selection after deletion.

7. **Criterion verification and regression**
   - Map every scenario in the four delta specs to its focused Domain/Application/Integration/headless test in `verification.md`.
   - Run focused tests, `dotnet test .\\FusionCanvas.sln`, strict OpenSpec validation, and changed-scope migration/security/UI review. No real-desktop Appium journey is warranted because native windows, OS-specific input, or desktop integration are not acceptance dependencies.
