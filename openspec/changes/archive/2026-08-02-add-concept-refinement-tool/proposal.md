# Proposal: add-concept-refinement-tool

## Why

GitHub issue #85: the Concept stage today offers three free-text fields (Concept idea, Phrase, Graphic direction) and nothing else. Moving from a raw base idea to a balanced design triangle — where idea, phrase, and graphic all reinforce each other — is entirely manual. The AI foundation delivered by `openrouter-api-configuration` (provider-neutral `IAiTextGenerationService`, an `AiRequestPurpose.Concept` profile, availability reporting) already anticipates this workflow, but no Concept-stage interaction uses it. This module delivers the Concept refinement tool: an AI-assisted, iterative loop that initializes the design triangle from the item's base idea and then fine-tunes or changes each corner in context of the others, with session history, rollback, and a live completeness score.

**Module outcome:** A creator with AI configured can open an item at the Concept stage, initialize the design triangle from its base idea, iteratively fine-tune or replace each corner with AI assistance, review and roll back through a session history, edit any corner manually at any time, and see a live completeness score — all inside the existing Concept stage section, with the current automatic-save draft model unchanged.

## What Changes

- Add a **Concept refinement section** to the existing Concept stage surface in the document window (below the three creative fields), following the issue author's placement preference and the current inline layout.
- Add an **Initialize from base idea** action that asks AI to derive Concept idea, Phrase, and Graphic direction from the item's original Idea text and the resolved workspace context. Initialization is always manually triggered; entering the Concept stage never calls AI implicitly.
- Add **Fine tune** and **Change** actions for each of the three corners. Fine tune improves the corner while preserving its direction, in context of the other two corners; Change proposes a materially different direction for that corner that still works with the other two. Phrase results are normalized to one line, matching the existing Phrase constraint.
- Keep all three corners **editable text fields**; manual edits and AI-applied values share the same draft and automatic-save path (field-exit commit / commit drain, stage-aware expected-state guard) defined by `listing-inspector`.
- Add a **session-scoped history pane** listing each refinement action (initialize, fine-tune, change, and manual field commits) with rollback: selecting a history entry restores that entry's triangle values into the drafts. History is transient per item document session, like Photoshop/Affinity history; it is not persisted and does not survive closing the item document.
- Add a **live completeness score** computed deterministically in the Domain layer from the current triangle values (presence and balance of the three corners). It needs no AI call, updates on every value change, and communicates remaining optimization potential, not design quality.
- **Gate AI actions on availability** via `IAiTextGenerationService.GetAvailabilityAsync(AiRequestPurpose.Concept)`: actions remain visible but disabled with actionable guidance when unavailable (missing key, missing model/profile, inaccessible credential store), mirroring the Ideation gating pattern. The heuristic score remains live even when AI actions are disabled.
- Bundle a **design triangle guidance markdown document** with the app and include its content as prompt context for refinement operations. This module ships a short placeholder description derived from the issue; the maintainer will replace it with the formal document later. No UI reads or displays the document in this module.
- **Spec drift reconciliation (documentation-level):** remove the stale `Listing inspector edits core creative fields with explicit save` requirement from `listing-inspector`, which directly contradicts the accepted automatic-save requirement in the same capability and the implemented behavior. This module's AI-applied-value commits build on the automatic-save requirement, so the contradiction must be resolved for the delta to be implementable. The related stale `Item text uses an explicit guarded save` requirement in `basic-product-workflow` is noted as follow-up drift and intentionally left untouched by this module.
- One AI operation runs at a time per item document; controls disable while running; switching item, tab, or closing the document cancels the in-flight operation and late results never write into another item's draft. Failures leave drafts and history unchanged with a recoverable inline error.

## Capabilities

### New Capabilities

- `concept-refinement`: AI-assisted iterative refinement of the Concept-stage design triangle — manual initialization from the base idea, per-corner fine-tune/change operations, draft integration through the automatic-save path, session-scoped history with rollback, a deterministic live completeness score, AI-availability gating, bundled design-triangle guidance as prompt context, and single-operation concurrency with cancellation.

### Modified Capabilities

- `listing-inspector`: Remove the stale, contradictory `Listing inspector edits core creative fields with explicit save` requirement (superseded by the accepted automatic-save requirement in the same capability). No behavior change.

## Impact

- **Domain:** New design-triangle completeness scoring rule (framework-free, fully testable). No provider, UI, or persistence references.
- **Application:** New concept-refinement use cases and ports: build refinement context, initialize/fine-tune/change operations against `IAiTextGenerationService` with `AiRequestPurpose.Concept`, prompt assembly from the bundled guidance document + item/workspace context (excluding credentials and operational fields, per the established generation-payload discipline), phrase single-line normalization, and session history state management.
- **Integration:** Loading of the bundled design-triangle markdown guidance document behind an application-facing contract. Reuses the existing OpenRouter adapter, credential store, and configuration resolution; no new provider, schema, or migration.
- **App:** Refinement section UI inside the existing Concept stage border in `MainWindow.axaml` (per-corner Fine tune/Change buttons, Initialize action, score display, history list with rollback, disabled-with-guidance states, busy/cancellation states); view-model composition on `MainWindowViewModel`/`ItemInspectorViewModel`; headless view tests for material binding, control-state, and selection behavior.
- **Persistence and compatibility:** No schema change. AI-applied values and rollback persist through the existing item-inspector automatic-save commits. History is session-only.
- **Dependencies:** Builds on the merged code and pending spec deltas of `openrouter-api-configuration` (`IAiTextGenerationService`, Concept AI profile, availability contract). That change must be synchronized/archived before or together with this one. The Ideation integration (`integrate-ideation-openrouter-snowclones`) is a pattern reference, not a dependency.
- **Primary risks:** prompt quality/determinism for fine-tune vs change semantics (mitigated by guidance document and focused prompts); accidental AI cost (mitigated by manual-only triggers and one-operation-at-a-time); late async results corrupting a different item's draft (mitigated by cancellation + identity-checked application); score perceived as quality judgment (mitigated by labeling it completeness); scope creep into persisted concept versions (explicitly out of scope).
- **Verification approach:** Domain heuristic unit tests; Application use-case tests with fake AI service (availability states, operation results, failures, cancellation, payload discipline, normalization); headless Avalonia view tests for the refinement section (button enablement, busy/disabled states, history listing and rollback selection, score updates, unavailable guidance); criterion-level evidence in `verification.md`; strict OpenSpec validation; `dotnet test .\FusionCanvas.sln` baseline.
- **UX preflight (user-facing):** Primary workflow = a creator refining one item's concept, occasionally (a few times per item). Surface = primary workspace inside the existing Concept section, not a dialog (issue author's preference; matches current inline tool layout). Persistent footprint = one compact section below the fields; history is capped/collapsible so it does not displace Notes and Tags. States resolved: empty (no base idea → Initialize disabled with guidance), unavailable (AI not configured → actions disabled with reason), busy (one operation running → controls disabled), success (values applied to drafts, history entry appended, score updates), failure (recoverable inline error, drafts/history unchanged), rollback (entry selection restores drafts), read-only (earlier-stage review → whole section disabled). Keyboard: actions reachable in logical order after the fields, with accessible names; no pointer-only flows. Drafts/cancellation follow the existing automatic-save + commit-drain rules; closing/switching cancels in-flight AI work without prompting.
- **Non-goals:** Persisted concept versions or persisted refinement history; branching a refined concept into a new item; AI coherence scoring or any AI-computed score; automatic AI calls on stage entry; image/design generation; streaming responses; prompt/response persistence; a UI for the design-triangle guidance document; reconciling the stale `basic-product-workflow` explicit-save requirement (noted follow-up).
