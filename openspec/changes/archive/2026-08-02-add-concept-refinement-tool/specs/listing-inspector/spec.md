## REMOVED Requirements

### Requirement: Listing inspector edits core creative fields with explicit save
**Reason:** Superseded by `Listing inspector edits core creative fields with automatic save`, which the archived fix-main-window-usability change produced by renaming and modifying this exact requirement. The explicit-save variant was accidentally re-introduced by the later archived basic-product-creation-workflow change, leaving two contradictory save-model requirements in the accepted capability. The implemented behavior, `docs/ui-guidelines.md`, and the automatic-save requirement all agree on field-exit automatic save with silent commit before context transitions and no Save/Discard prompt.
**Migration:** No behavior or data migration. Item working title, current-stage text, and Notes continue to persist through the automatic-save rules of `Listing inspector edits core creative fields with automatic save` and `Listing inspector commits pending edits when the context changes`. Stage-ownership rejection from the removed requirement's `Save targets a non-current stage` scenario continues to be enforced by the automatic-save requirement's current-stage ownership framing and the stage-relevant creative fields read-only behavior.
